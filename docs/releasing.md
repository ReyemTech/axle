# Releasing Axle

## Cut a release

Releases are automated with [release-plz](https://release-plz.dev) (`release-plz.toml`,
`.github/workflows/release-plz.yml`):

1. Every push to `main` opens or updates a **release PR**. It bumps `version` in
   `Cargo.toml` and `Cargo.lock` and adds a `CHANGELOG.md` section built from the
   conventional commit messages (`feat:`, `fix:`, `feat!:` …). Edit the changelog in that PR
   if the wording needs work.
2. **Merging the release PR** creates the tag `vX.Y.Z`. Nothing else is released by
   release-plz: it does not publish to crates.io and does not create the GitHub Release.

Versions come from git tags (`git_only = true`), not from crates.io. Before 1.0, a breaking
change bumps the minor version and everything else bumps the patch.

### First release (v0.1.0)

release-plz waits until a `v*` tag exists, so the first one is tagged by hand on the merge
commit of the MVP. `CHANGELOG.md` already has the `0.1.0` section.

```sh
git switch main && git pull
git tag v0.1.0 && git push origin v0.1.0
```

### Manual release (fallback)

Bump `version` in `Cargo.toml`, run `cargo build` so `Cargo.lock` follows, add the
`CHANGELOG.md` section, commit to `main`, then `git tag vX.Y.Z && git push origin vX.Y.Z`.
The tag must equal the Cargo version.

Three workflows run on the tag:

| Workflow | What it does |
|---|---|
| `release.yml` (generated by `dist`, do not hand-edit) | Builds macOS and Linux binaries for x86_64 and arm64, checksums, GitHub Release, shell installer, Homebrew formula push |
| `crates.yml` | After `Release` succeeds, runs `cargo publish` |
| `docker.yml` | After `Release` succeeds, packages the released Linux binaries into the multi-arch image (`Dockerfile.release`, no compiling) for GHCR (and ECR if configured), plus the Helm chart |

After changing `dist-workspace.toml`, regenerate with `dist generate` and commit the result.
Pull requests run `dist plan` to catch breakage early. The arm64 Linux binary builds natively
on `ubuntu-22.04-arm`, so aws-lc-rs needs no cross toolchain. Both Linux binaries build on
Ubuntu 22.04 (glibc 2.35), so they run on older distros and in the distroless Debian 12 image.

## One-time owner setup

- [ ] Create a fine-grained PAT for release-plz: resource owner **ReyemTech**, repository
  **ReyemTech/axle** only, permissions **Contents: read and write** and **Pull requests:
  read and write**. Save it in `ReyemTech/axle` as secret `RELEASE_PLZ_TOKEN`. It must not
  be the default `GITHUB_TOKEN`: tags pushed with that token do not start other workflows, so
  no release would build. Until it is set, the Release PR workflow fails with a message
  saying so.

- [x] `ReyemTech/homebrew-tap` already exists (it holds the stint casks). dist adds `Formula/axle.rb` next to them, so `brew install reyemtech/tap/axle` works.
- [ ] Create a fine-grained PAT limited to `ReyemTech/homebrew-tap` with **Contents: read and write**. Save it in `ReyemTech/axle` as secret `HOMEBREW_TAP_TOKEN`. The stint repo already has a secret with this name; you can reuse the same token if it is scoped to the tap, or make it an org-level secret shared by both repos.
- [ ] Create a crates.io API token (scope: publish-new and publish-update) and save it as secret `CARGO_REGISTRY_TOKEN`.
- [ ] Optional ECR mirror (nothing happens until `ECR_REGISTRY` is set):
  - [ ] Create the ECR repository (`axle`, or any name you put in `ECR_REPOSITORY`).
  - [ ] Add the IAM OIDC identity provider `token.actions.githubusercontent.com` with audience `sts.amazonaws.com`.
  - [ ] Create an IAM role with the trust policy below and the push policy below. Save its ARN as secret `AWS_ROLE_ARN`.
  - [ ] Set repository variables:

| Variable | Example | Default |
|---|---|---|
| `ECR_REGISTRY` | `123456789012.dkr.ecr.us-east-1.amazonaws.com` or `public.ecr.aws/<alias>` | unset = ECR push off |
| `ECR_REPOSITORY` | `axle` | `axle` |
| `AWS_REGION` | `us-east-1` | `us-east-1` |
| `ECR_REGISTRY_TYPE` | `private` or `public` | `private` |

ECR Public only works in `us-east-1`.

### Trust policy

Replace `ACCOUNT_ID`. `docker.yml` starts from `workflow_run`, which runs on the default
branch, so the OIDC subject is `main`, not the tag.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::ACCOUNT_ID:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
        },
        "StringLike": {
          "token.actions.githubusercontent.com:sub": "repo:ReyemTech/axle:ref:refs/heads/main"
        }
      }
    }
  ]
}
```

### Push permissions (private ECR)

Replace `REGION`, `ACCOUNT_ID` and the repository name if different.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "ecr:GetAuthorizationToken",
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ecr:BatchCheckLayerAvailability",
        "ecr:BatchGetImage",
        "ecr:CompleteLayerUpload",
        "ecr:InitiateLayerUpload",
        "ecr:PutImage",
        "ecr:UploadLayerPart"
      ],
      "Resource": "arn:aws:ecr:REGION:ACCOUNT_ID:repository/axle"
    }
  ]
}
```

For ECR Public, use `ecr-public:GetAuthorizationToken` and `sts:GetServiceBearerToken` on `*`,
and the same layer and `ecr-public:PutImage` actions on
`arn:aws:ecr-public::ACCOUNT_ID:repository/axle`.
