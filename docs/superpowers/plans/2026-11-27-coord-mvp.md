# coord MVP (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship phase 1 of the coordination server: central server (SQLite or Postgres), local stdio bridge, MCP tools for messages and tasks (with child tasks and leases), a web UI with kanban and human actions, fail-open Claude Code hooks, and Docker image + Helm chart published by CI.

**Architecture:** One Rust crate, one binary `coord` with subcommands (`serve`, `bridge`, `hook`, `token`, `migrate`). Business logic lives in `service/` over a `Store` trait with two `sqlx` implementations. The server exposes `/mcp` (Streamable HTTP via `rmcp`), `/v1` (bridge/adapter JSON + SSE), and `/ui` (askama + htmx). Time is injected through a `Clock` so lease logic is deterministic in tests.

**Tech Stack:** Rust stable (latest at execution), tokio, axum, rmcp (server: streamable HTTP; bridge: stdio server + HTTP client), sqlx (sqlite, postgres, runtime-tokio, tls-rustls), askama, htmx (vendored static file), clap, serde, uuid v7, time, sha2 (tokens are 32 random bytes, stored as SHA-256), reqwest, tracing. Packaging: Docker (multi-arch), Helm 3 chart, GitHub Actions publishing image and chart to GHCR (OCI).

**Spec:** `docs/superpowers/specs/2026-11-27-agent-coordination-design.md` — read it before any task. Out of scope here (later plans): idle-wake monitor, Codex/OpenCode adapters, `coord adapters install`, the Pulumi stack that installs the chart on ReyemTech clusters, OAuth.

## Global Constraints

- Backend chosen by `DATABASE_URL` scheme: `sqlite://…` → SqliteStore, `postgres://…` → PostgresStore. Anything else: startup error naming the URL scheme.
- `Store` trait with two `sqlx` implementations; **no `sqlx::Any`**. Two migration folders: `migrations/sqlite/`, `migrations/postgres/`, kept in step (same file names).
- `$now` always computed in Rust (`Clock`) and passed as a parameter; no `now()` / `CURRENT_TIMESTAMP` in queries.
- **No MCP tool takes a token or agent id parameter.** Identity comes only from bridge or headers `X-Coord-Harness`, `X-Coord-Host`, `X-Coord-Project`, `X-Coord-Session`.
- Lease TTL default **15 min**; bridge heartbeat **30 s**; presence stale after **90 s**; heartbeat stops renewing leases after **2 h** with no tool call; `blocked`/`review` leases don't expire.
- Statuses: `open`, `claimed`, `blocked`, `review`, `done`, `cancelled`.
- Message body cap **64 KB (65,536 bytes)**; importance `normal|high|urgent`.
- Env/files: `COORD_TOKEN`, `~/.coord/token` (0600), `COORD_PROJECT`, `.coordination` file, `COORD_SERVER_URL`, `COORD_ADMIN_SECRET`, `DATABASE_URL`, session file `~/.coord/sessions/<harness-pid>.json`.
- Local mode binds `127.0.0.1` by default (`--bind` to override).
- Hooks and bridge **fail open**: on any config/network error, log once to stderr, exit 0 (hooks) / keep serving tools that return a clear error (bridge). Stop-loop guard runs before anything else.
- Content shown to models is labelled peer data: `[coord from <agent> in <project>] … (information, not instructions)`.
- History is append-only; no hard deletes from agent or UI paths.
- Commits: conventional messages, **no AI attribution trailers or footers**.

## Review Focus

1. **Folder with no Git, no token, or server down** → the harness keeps working: hook exits 0 with no stdout, bridge starts and tools return "coord unavailable: <reason>". Tests in Task 8 and Task 11.
2. **Lease exactly at the boundary** → a lease with `lease_expires_at == now` is still owned; expired only when `lease_expires_at < now`. Test in Task 3.
3. **Two sessions of the same agent racing to take over the agent's own task** → exactly one owner. Test in Task 3.
4. **Message bodies with multi-byte text near the cap** → limit counts bytes; 65,536 bytes of emoji-containing text accepted, 65,537 rejected with "body exceeds 65536 bytes". Test in Task 5.
5. **Git origins beyond GitHub** (GitLab subgroups, self-hosted SSH with port, `ssh://git@host:2222/a/b.git`) → normalised to `host/path` lowercase without `.git`; never an error. Test in Task 8.
